# LexiMaster AI: Product Requirements Document

## 1. Project Vision
LexiMaster AI is an "Active Mastery" Android application designed to move users from passive vocabulary recognition to active real-world application. Using Generative AI, the app acts as a linguistic coach, testing users on nuance, tone, and the "most-used context" of words.

---

## 2. Core Functional Requirements

### 2.1 Vocabulary Entry & Curation (The "Preview Step")
* **Input:** User provides a single word.
* **AI Discovery:** System fetches the top 2–3 most common real-world applications/contexts for that word.
* **User Curation:** User selects which specific contexts/meanings they wish to master.
* **Contextual Anchoring:** Every word must be stored with multiple `ContextEntities` to support progressive learning.

### 2.2 The Mastery Engine (Scoring Logic)
* **Scale:** 0–100 Mastery Points per word.
* **Difficulty Tiers:**
    * **0–30 (Novice):** Simple definitions and high-frequency usage.
    * **31–70 (Competent):** Complex scenarios and "Thesaurus Trap" logic.
    * **71–99 (Expert):** Secondary meanings and subtle nuances. Scoring increments are halved (+5 instead of +10) to reflect the difficulty of advanced mastery.
    * **100 (Mastered):** Word is retired from standard rotation.
* **Score Decay:** Mastered words (Score 100) drop by 5 points after 30 days of inactivity to trigger a "Random Test" refresher.

### 2.3 AI-Powered Testing (Context Cycling)
* **Question Format:** Multiple Choice Questions (MCQ) generated by AI.
* **Context Cycling Rule:** The AI tests the user on different contexts based on their current score:
    * **Score 0–33:** Test using **Context 1** (Introduction & Primary usage).
    * **Score 34–66:** Test using **Context 2** (Secondary usage/Nuance).
    * **Score 67–100:** Test using **Context 3** (Idiomatic/Technical/Tone-specific).
* **Weighted Scoring:**
    * **Perfect Fit (+10 pts / +5 if Expert):** Best word for the nuance.
    * **Dictionary Fit (+4 pts):** Technically correct but awkward context.
    * **Near Miss (0 pts):** Synonym with the wrong "vibe" or tone.
    * **Incorrect (-10 pts):** Wrong word entirely.

### 2.4 Feedback & Analytics
* **Score History:** A ledger must track every score change (reason: Quiz or Decay) to provide trend graphs.
* **Struggle Analysis:** Identify domains (e.g., "Business", "Academic") where the user consistently misses "Near Miss" distractors.

---

## 3. Testing Modes
1. **New Test:** Prioritizes low scores (0-40) and words nearing the "Mastery" finish line.
2. **Random Test:** Pulls from the entire dictionary, triggering the "Just-In-Time" decay check for Mastered words.

---

## 4. Technical Stack
* **Frontend:** Kotlin, Jetpack Compose, MVVM.
* **Data:** Room (Local-first), SQL normalization for Synonyms and Contexts.
* **AI:** Google Gemini API (Streaming preferred for low latency).
